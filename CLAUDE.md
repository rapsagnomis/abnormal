# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

(a/b)normal (bundle name `abnormal`): a Tauri v2 desktop app (Rust audio/analysis core + React/TypeScript UI) that measures a track (slot A) against a reference (slot B) — loudness, dynamics, tonal balance, stereo, EQ-match suggestions — and matches tracks against a pre-analysed music library. `PLAN.md` records design decisions and what each build phase added; update it when adding a phase-sized feature.

## Commands

`cargo` lives in `~/.cargo/bin`, which may not be on PATH in a non-login shell — prefix with `export PATH="$HOME/.cargo/bin:$PATH"`.

```sh
npm run tauri dev                                  # run the app (hot reload)
npx tsc --noEmit                                   # typecheck the UI (no linter is configured)
cargo test --manifest-path src-tauri/Cargo.toml    # Rust test suite
cargo test --manifest-path src-tauri/Cargo.toml loudness::   # one module / test by name filter
npm run tauri build -- --bundles app               # release .app in src-tauri/target/release/bundle/macos/
```

Installing a build means replacing `/Applications/abnormal.app` with the bundle (quit the app first).

All tests live in `src-tauri/src/tests.rs`, grouped in modules (`loudness`, `player_mode`, `psychoacoustics`, `dynamics`, `spectrum_and_stereo`, `activity_and_spectrogram`, `eq`, `bundle`) plus top-level tests. Synthetic-signal tests always run (EBU Tech 3341/3342 cases, ISO 532-1 / DIN 45692 / Daniel & Weber references, known DR, spectra, correlations, the mixer without a device). Tests needing real audio silently pass unless their env vars are set: `SONIC_TEST_AUDIO` (dir of sine fixtures, see file header), `SONIC_BENCH_FILE`, `SONIC_DUMP_FILE`+`SONIC_DUMP_JSON`, `SONIC_EQ_TRACK`+`SONIC_EQ_REFERENCE`, `SONIC_SECTIONS_FILE`, `SONIC_DEEMIX_SEARCH` (starts Deemix headless in a temp folder and searches Deezer, no login), `SONIC_LIBRARY_DIR` (indexes a folder — point it at one album, the full library takes ~20 min). Use `-- --nocapture` to see their printed output.

The dev profile builds the app crate at opt-level 1 and dependencies at 3, because DSP is unusably slow unoptimised; tests use the same profile.

## Architecture

**Audio stays in Rust.** `decode.rs` (symphonia: mp3, flac, wav, aiff, and AAC/ALAC in m4a or ADTS .aac; not .m4p or ogg) produces `AudioData` (planar f32 at the file's own rate), kept per slot in `AppState.tracks`. The UI only ever receives downsampled peaks and analysis results. Playback (`player.rs`) uses a separate copy resampled to the device rate: one cpal stream plays every slot simultaneously with independent playheads/loops, and the A/B switch only crossfades gains; in player mode (`set_player_mode`, lane order) only the heard track advances and the mixer itself moves on to the next loaded lane when it ends. Loudness matching is a per-slot trim that only attenuates, except a track the user normalizes (lane button), which may be raised up to its headroom (true peak to −1 dBTP).

**One analysis path for everything.** `lib.rs::analyze_range(audio, start, end, curves)` runs loudness → dynamics (reuses loudness's per-100 ms `Blocks`) → spectrum (normalised by integrated loudness) → stereo, and builds a `similarity::Features` fingerprint. Whole tracks are `0..frames`, selections are a frame range — the same code. Both the `analyze` command and library indexing call it; `curves = false` skips the over-time curves, `psycho = false` (library) skips sharpness and roughness (`psycho.rs`: Zwicker loudness ISO 532-1, DIN 45692 sharpness, Daniel & Weber roughness, ported from MoSQITo, at matched loudness of 75 dB SPL).

**Shared frequency grid.** `spectrum::grid()` (20 Hz–20 kHz, 24 points/octave) is the x-axis for every spectrum, width curve, EQ target, and the tonal part of the fingerprint (every 8th point), so arrays from A, B and the library line up index for index. Changing the grid changes all of these.

**Library (`library.rs`, `similarity.rs`).** At startup (`setup` in `lib.rs`) a background thread scans `~/Music/albums` recursively and analyses files that are new or changed (size + mtime) with ≤ 4 workers; deleted files are dropped; failures are stored so they aren't retried. The DB is `library.json` in the app data dir (`~/Library/Application Support/com.simongaspar.soniccompare/`), saved atomically every 20 s. **Bump `DB_VERSION` whenever `Features` or the analysis feeding it changes**, otherwise stale fingerprints are compared with new ones. Entries also hold tags (`meta`: title/artist/album, cover thumbnail in `covers/` next to the DB, served via the asset protocol), read by probe only and backfilled for older entries without a re-analysis; copies with identical fingerprints (`Features::identity`) are shown once. Similarity: per-value z-scores using the library's spread, RMS per group (tonal / dynamics / stereo), weighted combination, score = 100·e^−d. Progress reaches the UI via the `library-status` event. `standing.rs` places the mix and reference among the library (percentiles of qualities read off `Features` + integrated loudness), whole library or the closest N.

**Deezer downloads (`deemix.rs`).** The Library drawer (⌘K, `LibraryDrawer.tsx`) searches Deezer and downloads FLAC into the library through the Deemix desktop app (`/Applications/deemix-gui.app`) without opening it: its bundled HTTP server is started headless (`ELECTRON_RUN_AS_NODE=1`, `--singleuser`, free port, `DEEMIX_DATA_DIR` = `deemix/` in our app data), lazily on first use and killed on exit. Deemix logs in per HTTP session, so the `ureq` agent keeps the cookie; the ARL is saved by Deemix in that data dir, never by us. Finished downloads trigger a library rescan.

**Frontend.** `src/App.tsx` owns all state (per-slot arrays `PerSlot<T>` over the 50 engine slots (`SLOT_COUNT` in `api.ts`, `player::SLOTS` in Rust; per-slot data crossing IPC is a `Vec`, as serde stops at 32-element arrays) — two lanes and up to 48 extra ones, numbered 1–50 by their display order in `order` (numbers follow position, so removing 3 relabels 4 and dragging a lane reorders, without moving audio; colours go with the track, not the number: `--lane-N` is pointed by `colorOf` in `App.tsx` at the song's picked colour (`LaneVersions.color`, chosen in the versions drawer, saved in sessions), else its cover's accent, else its engine slot's palette hue `--hue-(slot+1)`); analysis, EQ match and EQ audition are one-to-one on the *compared pair* — `subject` (the song listened to; listening to a reference keeps its song) and that song's `reference` (derived by `referenceOf`, see below; `NO_REFERENCE` = −1 when it has none) — exposed to the panel through `PairContext` (`src/lib/pair.ts`), whose `--a`/`--b`/`--series-a`/`--series-b` are repointed at the pair's lane colours (`--lane-N`, `--series-lane-N`); `match_eq` takes the pair's slots, a `loadSeq` counter to discard results for replaced tracks, a `latest` ref for once-registered keyboard/drag-drop handlers). Files opened from Finder (bundle `fileAssociations`) arrive as `RunEvent::Opened`, are queued in `AppState.opened` and drained by the UI via `take_opened_files` on startup and on the `open-files` event; they start playing unless something already is. `src/lib/api.ts` mirrors the Rust types (serde `camelCase`) and wraps every `invoke` — keep the two in sync by hand. Metric tables are data-driven from `src/lib/metrics.ts` (`SECTIONS`); the EQ match section (in the Tonal tab) and the Library drawer have their own views. Markers (timestamped notes, N) are stored in `markers.json` in the app data dir (`markers.rs`), keyed by `decode::audio_id` (SHA-256 of the decoded samples, `TrackInfo.audioId`) so they survive moves and renames, with each entry's known paths as a fallback that carries notes over to a re-bounce at the same path. A lane holds a song with one or more versions (`versions: PerSlot<LaneVersions>` in `App.tsx`, edited in `VersionsDrawer.tsx`, opened from the lane's title tile): only the version in front is loaded in the engine slot, and switching loads the other file into the same slot at the same playhead time (`loadFile(.., { keepVersions, switching, at })`), keeping selection, loop and zoom. A song may also have its own references (`LaneVersions.references`, `referenceFront`, edited in the same drawer): the one in use is loaded in a hidden engine slot (`companions` in `App.tsx`, taken from the end of `EXTRA_SLOTS`, never in `order`, labelled `R` + the song's number, `--lane-rN`) by a reconciling effect over `versions`, and rendered as a nested `TrackLane variant="reference"` at the bottom of its song's lane. The session's default reference (`defaultRef`, a file) is loaded the same way into `defaultSlot` (label `R`, `--lane-r`) and shown as a strip above the lanes (`variant="default"`, first row of the lanes grid, `data-default-ref` for drops). There is no pin: a song's reference is what `compareWith` says (another lane, or `"default"`, picked in `ComparedWith.tsx`), else its own reference in use, else the default. Export as Zip (`bundle.rs`, `wav.rs`) writes every lane's front version, tagged, with an optional cover (embedded in FLAC/MP3, and `cover.jpg` in the zip). Every version of a song with several is prepared ahead (`prepared.rs`, `prepare_versions`): decoded, resampled and fully analysed by one background worker, kept per path and checked against size + mtime, within a 4 GB budget (past it only the analysis is kept); `load_track` swaps in a prepared buffer and `analyze` returns the cached whole-track report (raw JSON via `tauri::ipc::Response`); `version_loudness` reads each prepared version's integrated loudness for a lane's Match Loudness (each version turned down to the quietest). Sessions (`sessions.rs`) save the lanes in order, each with its name, versions and front version, as a `.abnormal` JSON file (v2; v1's flat track list still opens), each file by absolute and relative path plus a macOS bookmark and an identity (`relink.rs`) so files renamed or moved outside the app are found again on open (the session is then re-saved with their new paths) (also a registered document type, routed from `take_opened_files` by extension) and keep the recent ones in `recent_sessions.json`; opening one replaces every lane (`replaceTracks` in `App.tsx`). `Features` from an analysis report is opaque to the UI and passed back unchanged to `similar_tracks`, so matching works for selections too.
